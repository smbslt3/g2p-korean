# 한국어 발음 구간 평가

`tools/evaluate_pronunciation_spans.py`는 원문 문장의 일부 구간에 대해서만 정답을 확보한 자료를 채점한다. 변환 실행과 정답 검토는 평가기 밖에서 수행하고, 사례와 전체 출력은 UTF-8 JSONL로 전달한다. 도구는 Python 표준 라이브러리만 사용한다.

```powershell
python tools/evaluate_pronunciation_spans.py --cases cases.jsonl --outputs outputs.jsonl --report report.json
```

사례의 필수 필드는 `id`, NFC 문자열 `input`, `target`의 `start`·`end`·`surface`, `judgment`, `accepted_pronunciations`, `category`, `family_id`, `split`, `sources`다. 좌표는 Python Unicode code point 기준이며 끝을 포함하지 않는다. `input[start:end]`는 `surface`와 같아야 한다. 하나의 문장에 여러 대상 구간을 선언할 수 있다.

`judgment=verified`만 정확도 분모에 포함한다. `pending`, `policy_dependent`, `data_error`, `unalignable`은 상태별 건수와 제외 사유를 보존한다. 이 상태는 평가 목적에 대한 판단이며 원본 데이터셋이 본래 과제에 부적합하다는 판정으로 확대하지 않는다. 허용 복수 발음과 발화 경계 조건은 출력을 보기 전에 정해야 한다.

출력 행은 `id`와 전체 문자열 `output`을 가진다. 실행 실패는 `output=null`, `error`로 기록한다. `complete`는 선택적인 파이프라인 완료 정보이며 정확도를 결정하지 않는다. 검증된 정답의 누락·실행 실패·정렬 실패는 정확 일치 실패로 집계하고 종류를 따로 표시한다.

동일 좌표로 구간을 추출하려면 전체 출력이 NFC이고 길이와 공백·문장부호 위치를 보존해야 한다. 이 검사는 현재 구현의 위치 보존 특성을 확인하는 제한된 경로다. 다른 엔진의 축약·확장·문장 재배열에 대한 일반 정렬을 보장하지 않는다. 외부 어댑터가 별도로 검증한 `target_output`을 주면 그 정렬 방식을 결과에 명시한다.

`frequency`는 기본 1인 양의 정수다. 실제 문장 사례를 선별했으면, 해당 어휘 유형의 다른 문맥까지 합한 빈도를 그 문장의 가중치로 쓰지 않는다. 반복 빈도를 사용한 점수와 고유 사례 점수를 함께 보고한다. `family_id`, 동일 원문, 선택적인 `leakage_group_ids`와 출처의 `source_group_id`가 개발·평가 분할을 가로지르면 거부한다. 선언되지 않은 의미적 유사성까지 자동 검증하는 것은 아니다.

주 지표는 허용 발음 집합에 대한 대상 구간의 정확 일치다. 선택적인 `accepted_sentence_pronunciations`가 있으면 전체 문장 일치를 별도로 계산한다. 자모 기호 편집률은 한글 음절의 초성·중성·종성을 구분한 기호열과 나머지 비공백 문자 기호의 Levenshtein 거리다. 복수 허용 발음에서는 최소 편집 수를 택하고, 동률이면 정규화한 발음의 유니코드 순서로 결정한다. IPA·음향 음소 오류율로 해석하지 않는다. 정렬·출력이 없어 기호 비교가 불가능한 건수도 따로 보고한다.

영문 치환으로 전체 출력 길이가 달라져도 원래 표적을 문자열 검색으로 찾지 않는다.
동일 변환 실행의 정확한 문자 source span에서 연속된 표적 출력 좌표를 확보한 경우
명시적인 `target_output`으로 전달할 수 있다. 근거가 거칠거나 여러 위치에 대응하면
정렬 실패로 남긴다. 참조 발음을 정렬 위치 선택에 사용하지 않으며, 정렬 보완을
발음 정확도 개선으로 계산하지 않는다.

실제 Kiwi를 쓰는 실행과 검증된 형태소 분석을 제공하는 대조 실행은 별도 출력 파일로 채점한다. 평가 자료·실행 코드·Kiwi 버전과 출력의 연결은 실행 기록에 남긴다. 개발에 노출된 사례의 성공을 전체 한국어 정확도나 경쟁 구현체 전체에 대한 우위로 확대하지 않는다.

## 외래어와 표기 동등성의 정답 승인

외래어 표제어의 철자, 사전의 발음 정보 생략, 일반 음운 규칙만으로 유일한 규범
발음을 승인하지 않는다. 직접 발음 처방과 현실 발음의 기술을 구별하고, 직접 처방이
없으면 평가 목적에 맞는 목표 정책을 출력 열람 전에 선언한다. 근거가 부족하면
`policy_dependent`로 둔다. 이는 가능한 모든 발음을 정답으로 허용한다는 뜻이 아니다.
[국립국어원 상담](https://www.korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=90&pageIndex=1&qna_seq=327506)은
일부 외래어의 발음이 규범적으로 정해져 있지 않음을 설명한다. 이 유사 사례를
모든 외래어에 적용하는 직접 처방으로 확대하지 않는다.

경구개음 뒤 j계 모음처럼 동등한 발음 표기가 있으면, 적용 범위와 대칭 정규화 함수를
평가 전에 고정해 보충 지표로 보고할 수 있다. 엄격 일치 점수와 원시 실패는 유지하며,
표기 동등성 증가를 음향 정확도 개선으로 부르지 않는다. 출력 열람 뒤 정답 근거의
부족이 발견되면 원래 참조·분모·점수를 보존한 채 타당성 보류를 표시한다. 후속 정답은
별도 버전으로 검토하며 기존 결과가 성공으로 바뀐 것처럼 재집계하지 않는다.

## 구의 읽기 조건과 전사 기호

`pause_assumption=no_pause`만으로 두 단어를 한 마디로 묶는 ㄴ 첨가와 일반 연음 중
하나를 확정하지 않는다. 국소 참조에는 필요한 경계 좌표와 읽기 조건을 함께 적고,
휴지·일반 연음·한 마디 묶음의 조건부 발음을 하나의 허용 집합으로 합치지 않는다.
[국립국어원 상담](https://korean.go.kr/front/onlineQna/onlineQnaView.do?mn_id=98&pageIndex=1&qna_seq=333041)은
구의 한 마디 읽기, 휴지, 연음을 구별한다. 이 다른 구의 설명을 개별 호격·감탄사 앞
발음의 직접 처방으로 확대하지 않는다.

자료군별 정의가 확인되지 않은 `에/`, `n/` 같은 기호를 발음·비발음·휴지로 자동 확정하지
않는다. 먼 기호가 국소 참조를 막는지는 실제 영향 범위로 판단하고, 직접 인접한 기호의
역할이 미확정이면 조건 보류를 명시한다. 검토자끼리 일치했다는 사실만으로 원문에 없는
운율 조건을 관찰 사실로 승격하지 않는다. 뒤늦게 조건 문제가 발견되면 맞은 출력과
틀린 출력 양쪽의 참조 전제를 같은 기준으로 검토하고 원시 점수는 유지한다.

## 정답 동결 전 경계 검토

`tools/pronunciation_reference_preflight.py`는 엔진을 실행하지 않고 사례 구조와
참조 창의 좌표·투영을 검사한다. 표적 앞뒤의 받침 경계, 된소리되기·관형형 검토
후보와 창 밖의 누락 문맥은 경고로 남긴다. 철자만으로 형태소·휴지·정답 발음을
확정하지 않으며, 경고가 없다는 사실도 정답 승인을 뜻하지 않는다.

```powershell
python -X utf8 -B tools/pronunciation_reference_preflight.py --cases cases.jsonl --report preflight.json --reading-profile connected_default --pause-assumption unspecified
```

보고서는 새 파일로만 쓴다. 종료 코드 `0`은 구조 오류 없음, `1`은 사례·참조 창
구조 오류, `2`는 실행·입출력 오류다. 검토 경고만 있는 경우에도 `0`을 반환한다.
`verified` 사례에는 표적을 포함하는 `reference_window`의 좌표와
`accepted_pronunciations`가 필요하다. 조건별 참조는 별도로 검사하며 원래 정답과
점수를 수정하지 않는다. 각 사례의 `reference_boundary_assumptions`에 읽기 조건과
휴지 가정을 명시하면 CLI 기본값보다 우선한다.
