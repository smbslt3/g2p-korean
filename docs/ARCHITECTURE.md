# 아키텍처

## 처리 순서

```text
원문
→ G2P.__call__ 또는 G2P.convert
  → normalize=True: KoreanTTSNormalizer로 한국어 발화형 생성
  → normalize=False: 입력 검증과 NFC만 적용
→ 영어 철자화와 한국어 표면 발음 생성
→ TTS
```

`g2p(text)`는 기본적으로 두 단계를 순서대로 실행합니다. 중간 발화형만 필요하면
`normalizer(text)`를 사용하고, 그 결과를 발음으로 바꿀 때는
`g2p(normalized, normalize=False)`로 중복 정규화를 생략합니다. 예를 들어
노멀라이저가 `16%`를 `십육 퍼센트`로 만들고, G2P 음운 단계는 이를
`심뉵 퍼센트`로 바꿉니다.

## 노멀라이저

```text
NFC·입력 검증
→ 보호 구간 탐지
→ 우선순위 토큰 스캔
→ 확정 규칙 변환
→ 필요한 숫자만 Kiwi 형태소 자질 기반 통계 모델 판별
→ 보존 정책·진단
```

통화·날짜·시간·범위처럼 표기가 읽기를 확정하는 토큰은 규칙이 담당합니다. 숫자
판별 모델은 카운터와 맨숫자처럼 문맥이 필요한 후보에만 개입하며, Kiwi가 제공한
주변 형태소 자질을 사용합니다. 분석 실패나 근거 부족 시 규칙 결과를 유지합니다.

문자열 API는 원문 span 생성을 생략하고, 일반 한글 문장은 토큰 스캐너도 건너뜁니다.
노멀라이저의 상세 `convert()`만 원문 좌표·rewrite·진단을 만듭니다.

## G2P

```text
선택적 KoreanTTSNormalizer
→ NFC·입력 검증
→ 보호·숫자·외국어 라우팅
→ ASCII 영어를 알파벳 이름으로 변환
→ HARD 경계 병합
→ Kiwi 형태소 분석으로 생산 규칙의 문맥 확인
→ 한국어 음운 규칙 적용
→ 최종 출력 검증
```

`normalize=False`는 입력 검증과 NFC를 유지하면서 TTS 노멀라이저의 숫자·단위·관용
읽기·사용자 사전 처리를 생략합니다. 따라서 이미 정규화한 발화형에만 사용합니다.
숫자는 노멀라이저가 읽고 G2P 음운 단계에서는 HARD 경계로 통과합니다.
지원하지 않는 문자는 보존합니다. 형태소 분석기와 음운 엔진은 교체할 수 없습니다.

형태소 경계 annotation은 PyPI 배포판의 공개 `Kiwi.tokenize()` 결과를 사용합니다.
활용형 분해로 겹치는 원문 좌표를 공유하는 token은 태그를 합칩니다. 길이 0인 형태소
태그는 같은 시작점의 다음 원문 구간에 붙이고, 표면형은 원문에서 복원해 비중첩
annotation으로 만듭니다. 사이시옷 위치는
`Kiwi.tokenize(split_complex=True, saisiot=True)`로 별도 확인합니다. 이 모드는 중첩
token, 길이 0인 `Z_SIOT`, 원문과 다른 형태소 표면형을 낼 수 있으므로 일반 분석과
하나로 합치지 않습니다.

기본 G2P 음운 단계는 공식 표준 발음법에서 일반화할 수 있는 생산 규칙을 합성하고,
고시 본문에 표기·발음이 직접 열거된 예 중 비모호한 113개를 한글 어절 전체의 정확
일치로만 보완합니다. 기존 형태소 규칙을 먼저 실행해 분석과 trace를 보존한 뒤 남은
차이만 `ko.official.enumerated`로 기록합니다. `발전`은 적용하지만 `발전기`,
`경제발전`, `발전은`에는 부분 일치를 확장하지 않으며 HARD 경계도 넘지 않습니다.

복수 발음이 가능한 표제어는 문맥 없이 한 발음으로 강제하지 않습니다. 외부 발음
사전을 포함하지 않으며, 어휘 지식이나 한자 의미가 필요한 발음은 추측하지 않습니다.

`G2P.convert()`는 노멀라이저의 상세 결과와 후단 파이프라인의 상세 결과를 모두
계산합니다. 두 단계의 진단 span 좌표가 다를 수 있으므로 `G2PResult.diagnostics`는
정규화와 발음 report를 분리하며, 각 report가 자신의 좌표 기준 문자열 `source`를
가집니다. 최종 `complete`는 두 단계의 완료 여부를 논리곱한 값입니다.

`G2P.__call__()`과 `G2P.convert()`는 같은 병합 segment와 음운 엔진을 사용합니다.
문자열 경로는 정규화된 중간 문자열에 임시 span을 만들어 상세 경로와 결과가 달라지지
않게 하며, 외부에는 표면 발음 문자열만 반환합니다.

## 정렬 계약

음운 엔진은 정규화문 문자를 삽입하거나 삭제하지 않습니다. 현대 한글 음절은 같은
위치의 현대 한글 음절로만 치환하며 공백·구두점·보존 문자는 위치를 유지합니다.
파이프라인은 segment별 길이와 전체 code point 길이를 내부 불변식으로 검사합니다.
공개 downstream 계약은 완료된 결과에서 다음과 같습니다.

```text
normalized_text[i] ↔ surface_pronunciation[i]
len(normalized_text) == len(surface_pronunciation)
```

## 공유 상태

- 정규식·규칙표: 모듈에서 한 번 컴파일
- Kiwi·숫자 모델: 프로세스에서 지연 생성 후 재사용
- 분석 결과·segment: 호출마다 생성, 상세 진단: `convert()` 호출마다 생성
- 사용자 사전: 생성자에서 trie로 컴파일하며 빈 사전은 보관하지 않음

배치 API는 순차 지연 iterator입니다. Kiwi의 `tokenize()`는 문자열 iterable을 받는
batch 분석도 지원하지만, 호출 시 입력 generator를 결과 요청보다 먼저 소비하고 뒤
항목의 형식 오류도 앞당길 수 있습니다. 현재 G2P는 정규화·라우팅 뒤 형태소 후보가
있는 항목만 분석하므로, 이 동작은 공개 API의 항목별 lazy 오류 시점과도 맞지 않습니다.
따라서 단순 `map`을 형태소 batch라고 부르거나 Kiwi batch로 넘기지 않으며, 각 항목의
기존 단일 변환을 순서대로 실행합니다. Python 스레드는 Kiwi 처리량을 높이지 못했으므로
내부 병렬 옵션을 두지 않습니다. 여러 코어가 필요하면 프로세스 워커를 사용합니다.
